# 23팀 DialAI 제출물 제작 가이드

이 문서는 MVP 개발이 끝난 뒤 발표자료, 데모 영상, Codex Build Log를 만들고
README에서 경로를 안내하기 위한 작업 순서와 검증 기준을 정의한다.

## 완료 조건

최종 Repository에 다음 자료가 모두 있어야 한다.

```text
README.md
docs/
├── build-log/
│   ├── README.md
│   ├── 23_김환_01_log.md
│   ├── 23_김환_02_log.md
│   └── 23_팀원명_01_log.md
├── demo/
│   ├── 23팀_DialAI_데모.mp4
│   └── README.md
└── presentation/
    ├── 23팀_DialAI_발표자료.pptx
    └── 23팀_DialAI_발표자료.pdf
```

README에는 위 발표자료, 영상, 팀원별 Build Log와 실제 배포 URL을 직접 연결한다.
파일이 생기기 전에는 존재하지 않는 링크를 완성된 것처럼 표시하지 않는다.

## 작업 시점과 순서

1. 핵심 사용자 흐름을 구현하고 코드를 프리즈한다.
2. 프론트엔드, 백엔드, 전화 연동, OpenAI Realtime, DB가 배포 환경에서 이어지는지 검증한다.
3. 팀원별 Codex Build Log를 세션 단위로 생성한다.
4. 검증된 기능과 결과만 사용해 README를 완성한다.
5. 같은 이야기 구조로 발표자료를 만든다.
6. 실제 배포 화면과 실제 전화 결과를 녹화한다.
7. Remotion으로 녹화본에 제목, 자막, 확대, 결과 요약을 합성한다.
8. 모든 링크, 파일, 영상 재생, 빌드와 배포를 다시 확인한다.

## 1. MVP와 배포 검증

아래 흐름 중 발표와 영상에서 보여줄 대표 시나리오 하나를 먼저 고정한다.

```text
사용자 요청
→ 웹 또는 Codex/MCP
→ 백엔드 작업 생성
→ 전화 발신
→ OpenAI Realtime 대화
→ 통화 결과 구조화
→ DB 저장
→ 사용자에게 결과 표시
```

코드가 로컬에서만 실행되는 것으로는 완료 처리하지 않는다.

- [ ] 프론트엔드가 공개 URL에서 열린다.
- [ ] 백엔드 API가 배포 환경에서 응답한다.
- [ ] 필요한 환경변수가 배포 환경에 설정되어 있다.
- [ ] DB 쓰기와 읽기가 실제로 성공한다.
- [ ] 전화 발신부터 결과 확인까지 대표 흐름이 한 번 이상 성공한다.
- [ ] 실패 시 사용자에게 이해할 수 있는 오류가 표시된다.
- [ ] `npm run lint`와 `npm run build`가 통과한다.
- [ ] README 실행 방법을 새 환경에서도 재현할 수 있다.

## 2. Codex Build Log 생성

### 파일 선정

원본은 각 팀원 컴퓨터의 다음 위치에 있다.

```text
~/.codex/sessions/YYYY/MM/DD/rollout-*.jsonl
```

각 JSONL 첫 줄의 `session_meta.payload.cwd`가 이 Repository의 절대 경로와
일치하는 세션만 후보로 삼는다. 최종 생성 직전에 다시 세어 당일 추가된 세션까지
반영한다.

다음 항목은 제출용 로그에서 제외한다.

- 다른 Repository에서 실행한 세션
- `hi` 같은 연결 확인만 한 세션
- 실제 작업이 없는 모델 설정 세션
- Claude Code에서 가져온 대화나 Claude 세션 이전만 수행한 세션

원본 JSONL 전체는 시스템 지침, 로컬 경로, 개인정보나 비밀값이 포함될 수 있으므로
그대로 Repository에 올리지 않는다. 제출용 Markdown으로 요약하고 민감정보를 다시
검토한다.

### 파일명과 번호

파일 하나가 Codex 작업 세션 하나에 대응한다.

```text
23_성함_01_log.md
23_성함_02_log.md
23_성함_03_log.md
```

번호는 팀원 순번이 아니라 해당 팀원의 유효한 세션을 시작 시각순으로 정렬한
순번이다. 한 자리 번호도 `01`처럼 두 자리로 맞춘다. 새로운 세션이 생기면 기존
번호 뒤에 이어서 추가한다.

김환의 경우 2026-08-16 13:54 기준으로 이 Repository에서 수행한 실질적인 Codex
작업 세션 14개를 확인했다. 이는 중간 집계이므로 코드 프리즈 후 다시 계산한다.

### 세션별 문서 내용

각 로그는 단순 대화 덤프가 아니라 다음 과정을 재구성한다.

```markdown
# Codex Build Log — 세션 01

- 팀: 23팀
- 작업자: 김환
- 세션 ID: ...
- 작업 시각: ...
- 작업 목표: ...

## 1. 계획과 위임
사용자가 Codex에 맡긴 문제와 제약을 요약한다.

## 2. 구현 또는 조사 과정
Codex가 확인한 파일, 선택한 접근, 만든 결과를 기록한다.

## 3. 시행착오와 반복 수정
잘못된 가정, 실패한 명령, 사용자 피드백, 수정 방향을 기록한다.

## 4. 오류 복구
오류 원인과 복구 방법이 있었던 경우 구체적으로 기록한다.

## 5. 검증과 결과
실행한 테스트, 빌드, 브라우저 확인 또는 조사 근거와 남은 한계를 기록한다.
```

시행착오나 오류가 없었던 세션은 없던 내용을 꾸며내지 않고 `해당 없음`이라고
쓴다. 세션 원문에서 확인할 수 없는 성공, 테스트, 배포 결과도 만들지 않는다.

현재 `scripts/codex-log.sh`는 여러 세션을 한 Markdown 파일로 합치는 이전 방식이다.
최종 로그 생성 전에 스크립트를 위 세션별 파일 규칙에 맞게 수정하거나, 동일한
규칙으로 세션별 파일을 생성해야 한다.

### 다른 팀원 로그 받기

각 팀원은 자신의 컴퓨터에서 자기 세션을 추출해야 한다. 전달받은 파일은 파일명과
민감정보를 확인한 뒤 모두 `docs/build-log/`에 넣는다. 같은 사람의 번호가 중복되거나
중간 번호가 빠지지 않았는지 확인한다.

## 3. README 완성

README는 심사자가 Repository에 들어왔을 때 보는 제출물 인덱스다.

- 프로젝트 이름과 한 문장 설명
- 대상 사용자의 문제와 해결 방식
- 대표 사용 흐름과 핵심 기능
- 실제 배포 URL과 데모 영상 경로
- 프론트엔드, 백엔드, AI, 전화 연동, DB, 배포 기술
- 로컬 실행 방법과 필요한 환경변수 이름
- 팀원별 역할과 실제 기여
- 발표자료 경로
- 팀원별 Codex Build Log 목록
- Value & Viability

README의 `[배포 URL]`, `[프로젝트 이름]` 같은 자리표시자는 제출 전에 모두 제거한다.
API 키, 전화 서비스 인증정보, DB 비밀키는 README나 Git 이력에 넣지 않는다.

## 4. 발표자료 제작

발표자료의 목적은 심사위원이 문제의 가치, 실제 작동 여부, Codex와의 협업 과정을
짧은 시간 안에 이해하도록 만드는 것이다. 권장 구성은 7장이다.

1. 문제: 전화로만 처리되는 업무의 대기와 반복
2. 기존 방식의 한계와 지금 가능한 이유
3. DialAI가 요청을 받아 전화를 완료하는 흐름
4. 실제 데모 시나리오와 결과
5. 프론트엔드·백엔드·전화·AI·DB 아키텍처
6. Codex의 계획 → 구현 → 수정 → 검증 사례
7. 대상 사용자, 기대 가치, 운영 가능성과 확장 방향

주장과 화면은 실제 MVP에서 검증된 내용만 사용한다. 외부 통계, 이미지, 서비스
정보를 사용하면 슬라이드 발표자 노트에 출처를 남긴다. 최종 PPTX는 모든 슬라이드를
렌더링해 글자 잘림, 겹침, 낮은 해상도와 자리표시자를 확인한 후 PDF도 함께 내보낸다.

## 5. 데모 영상 제작

권장 방식은 **실제 동작 녹화 + Remotion 편집**이다. Remotion은 React 코드로
MP4를 렌더링하고 Studio에서 미리 볼 수 있다.
공식 정보: <https://www.remotion.dev/>

완전히 합성한 UI 영상은 실제 MVP 증거가 약하므로 사용하지 않는다. 다음 순서로
60~90초 영상을 만든다.

1. 0~5초: 문제와 제품명
2. 5~15초: 사용자가 자연어로 전화 업무 요청
3. 15~45초: 실제 배포 앱의 작업 생성과 실제 통화 진행
4. 45~65초: 통화 요약, 예약 또는 문의 결과, DB 기록 확인
5. 65~80초: 전체 구조와 지원 채널 요약
6. 마지막: Repository와 배포 URL

화면 녹화 원본에는 API 키, 전화번호, 개인정보와 다른 팀의 화면이 보이지 않아야
한다. Remotion 소스는 재현 가능하도록 Repository에 남기고 최종 MP4는
`docs/demo/23팀_DialAI_데모.mp4`에 둔다. 제출 전에 다른 컴퓨터에서 영상과 음성이
정상 재생되는지 확인한다.

## 6. 최종 제출 점검

- [ ] PPTX와 PDF가 Repository에서 열리고 모든 슬라이드가 정상이다.
- [ ] MP4가 다운로드 및 재생되며 음성과 자막이 맞는다.
- [ ] 공개 배포 URL에서 대표 시나리오가 동작한다.
- [ ] 백엔드와 DB가 배포 환경에서 연결된다.
- [ ] 팀원별 Codex 세션이 각각 Markdown 파일로 정리되어 있다.
- [ ] README에서 모든 제출 자료로 이동할 수 있다.
- [ ] README의 자리표시자와 `TODO`가 없다.
- [ ] 비밀키, 개인정보, 원본 Codex JSONL이 커밋되지 않았다.
- [ ] 제출 브랜치의 `npm run lint`와 `npm run build`가 통과한다.
- [ ] Claude Code 산출물이나 Claude 세션을 Codex Build Log로 제출하지 않는다.
