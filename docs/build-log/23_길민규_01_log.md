# Design Direction

## 1. 디자인 목표

이 서비스는 화려한 AI 제품보다 **사용자가 안심하고 전화 업무를 맡길 수 있는 실용적인 업무 도구**처럼 보여야 한다.

핵심 인상은 다음 세 가지다.

- **신뢰감:** AI가 현재 무엇을 하고 있는지 명확하게 보여준다.
- **통제감:** 필요한 순간에는 사용자가 바로 개입할 수 있다.
- **간결함:** 전화 요청부터 결과 확인까지 복잡한 설정 없이 진행한다.

> 디자인 키워드: **Calm · Clear · Trustworthy**

---

## 2. 기본 디자인 원칙

### 업무 중심

첫 화면부터 기능 설명보다 사용자가 처리할 업무를 입력하도록 한다.

- 메인 문구: `어떤 전화를 대신 처리해드릴까요?`
- 입력 예시: `병원에 전화해서 다음 주 진료 일정을 변경해줘.`

### 진행 상태의 투명성

전화가 어느 단계에 있는지 항상 보여준다.

- 요청 내용 확인 중
- 전화 연결 중
- ARS 진행 중
- 상담사 연결 대기 중
- 상담 진행 중
- 사용자 확인 필요
- 완료 / 실패

### 중요한 정보 우선

통화 화면에서는 모든 로그를 같은 비중으로 보여주지 않는다.

1. 현재 진행 상태
2. 사용자 확인이 필요한 질문
3. 실시간 통화 내용
4. 세부 시스템 정보

### 과도한 AI 연출 지양

로봇 캐릭터, 네온 효과, 과도한 그라데이션, 음성 파형 애니메이션은 최소화한다. AI의 존재보다 **업무가 실제로 처리되고 있다는 사실**이 더 중요하다.

## 3. 화면 구조

MVP는 아래 4개 화면을 중심으로 구성한다.

### 3.1 업무 요청 화면

사용자가 처리할 전화 업무를 입력하는 시작 화면이다.

필수 요소:

- 큰 자연어 입력창
- 자주 사용하는 요청 예시
- 전화할 기관 또는 전화번호
- 필요한 고객 식별정보 입력 영역
- `요청 내용 확인하기` 버튼

식별정보는 주민등록번호를 기본값으로 두지 않고 기관별 정보 중심으로 표시한다.

- 병원 환자번호
- 전기·가스 고객번호
- 통신사 고객번호
- 보험 계약번호

### 3.2 전화 전 확인 화면

AI가 요청을 정리하고 부족한 정보를 사용자에게 질문하는 화면이다.

구성:

- AI가 정리한 업무 목적
- 확정된 조건
- 추가 확인 질문
- 선택형 버튼 또는 직접 입력
- `전화 시작` 버튼

예시:

> 변경 가능한 날짜가 여러 개라면 어떤 시간대를 우선할까요?

`오전 우선` `오후 우선` `상관없음`

### 3.3 실시간 통화 화면

서비스의 핵심 화면이다.

상단:

- 통화 대상 기관
- 통화 경과 시간
- 현재 상태 배지

본문:

- 상담사와 AI의 실시간 대화 내용
- 발화자를 명확하게 구분한 채팅형 기록
- 현재 수행 중인 단계 표시

하단 고정 영역:

- 사용자 추가 지시 입력창
- 사용자 확인이 필요한 경우 질문 카드와 선택 버튼

사용자 응답이 필요한 질문은 일반 메시지보다 강하게 강조한다.

예시:

> 상담사가 예약 가능한 날짜를 두 개 제안했습니다.

`8월 20일 오전 10시` `8월 22일 오후 2시`

### 3.4 결과 화면

통화가 끝난 뒤 결과를 빠르게 이해할 수 있도록 보여준다.

표시 순서:

1. **최종 처리 결과**
2. **통화 요약**
3. **전체 통화 내용**

완료 예시:

> 진료 일정 변경 완료
> 기존: 8월 18일 오후 3시
> 변경: 8월 22일 오전 10시

실패 예시:

> 일정 변경 실패
> 사유: 환자번호 확인 실패
> 진행 단계: 상담사 연결 완료 후 본인확인 단계에서 종료

## 4. 시각 디자인

### 컬러

전체 화면은 밝고 차분한 색을 사용한다.

- Background: `#F7F8FA`

- Primary: `#3157D5`
- Text Primary: `#171A21`
- Text Secondary: `#667085`

- Warning: `#C47A08`
- Error: `#D64545`

Primary 컬러는 주요 버튼과 현재 진행 상태에만 사용한다.

### 타이포그래피

- 기본 폰트: `Pretendard`, `Inter`, `system-ui`
- 본문: 15~16px
- 화면 제목: 24~28px
- 상태와 결과는 굵기 차이로 우선순위를 구분한다.

### 컴포넌트 스타일

- 카드 모서리: 12px
- 버튼 높이: 44~48px
- 얇은 테두리와 약한 그림자 사용
- 아이콘은 단순한 라인 아이콘 사용
- 한 화면에 강조 버튼은 하나만 둔다.

## 5. 상태 표현

통화 상태는 텍스트와 색상을 함께 사용한다.

| 상태    | 표시 문구            | 표현     |
| ----- | ---------------- | ------ |
| 준비    | 전화 내용을 확인하고 있어요  | 회색     |
| 발신    | 전화를 연결하고 있어요     | 파란색    |
| ARS   | ARS 메뉴를 진행하고 있어요 | 파란색    |
| 대기    | 상담사 연결을 기다리고 있어요 | 주황색    |
| 통화    | 상담사와 통화 중이에요     | 초록색    |
| 확인 필요 | 사용자의 확인이 필요해요    | 주황색 강조 |
| 완료    | 요청한 업무를 처리했어요    | 초록색    |
| 실패    | 업무를 완료하지 못했어요    | 빨간색    |

색상만으로 상태를 구분하지 않고 반드시 문구를 함께 표시한다.

## 6. 문구 스타일

문구는 친근하되 가볍지 않게 작성한다.

좋은 예:

- `전화하기 전에 두 가지를 확인할게요.`
- `현재 상담사 연결을 기다리고 있어요.`
- `상담사가 가능한 날짜를 두 개 제안했습니다.`
- `요청한 일정으로 변경이 완료됐어요.`

피해야 할 예:

- `제가 완벽하게 해결해드릴게요!`
- `AI가 마법처럼 전화해드립니다.`
- `잠시만 기다려주세요ㅎㅎ`

완료 여부와 실패 이유는 모호하게 표현하지 않는다.
